# Plan: API parity + agent-ergonomics wave → v0.5.0

Date: 2026-08-03. Owner: release coordinator. Branch: `feat/api-parity-0.5.0`.
Inputs: `work/audit-2026-08-03-spec-drift.md`, `work/audit-2026-08-03-docs-coverage.md` (two independent audits), live probes preserved in `work/probes-2026-08-03.md`.

## Why

The repo's promise is the full Exa API as an agent-first CLI. Two audits found drift: a retired endpoint family we still ship, a docs-only endpoint family we lack, a documented query param we cannot send, two advertised-but-unimplemented flags, and contract-level enum/schema changes. This wave restores **typed parity under D16/D40** — full coverage of the current typed API surface, with OpenAI-compat routes and MPP/x402 access modes intentionally deferred and recorded as decisions (they are compatibility/payment transports duplicating natively covered surfaces, not endpoint gaps).

Ground truth (preserved in `work/probes-2026-08-03.md`):
- `GET /research/v1` → HTTP 410, upstream tag `RESEARCH_RETIRED`.
- `POST /search` accepts both `category: "research paper"` (legacy) and `"publication"` (canonical); our typed allow-list (`src/cli/mod.rs:70-103`) rejects `publication` locally.
- `search --type deep-reasoning` already exists (the documented Research replacement).

## Design stance (the agent's-eye view)

Governing rule (agent-ergonomics One Rule): the first thing an agent instinctively tries must either work or fail with an exact, copy-pasteable next command.

1. **Retired ≠ vanished.** `research` becomes a local stub: exits 1 (usage), error code `research_retired`, no network call. Per-verb suggested commands: `research create "<query>"` interpolates the actual supplied query into `exa-agent search "<query>" --type deep-reasoning`; `research get <id>` / `research list` suggest `exa-agent search --help` (argument-free, real) and preserve any supplied id in `error.details.researchId`. The three generated ops, overlay entries, and fixtures are removed; stubs are callable locally but absent from `capabilities`.
2. **Accept both enum spellings on typed flags, send canonical, warn.** Exact mappings: `research paper`→`publication` (search + similar `--category`); `fiber_ai`→`fiber`, `particle_news`→`particle` (agent data-source provider). Coercion applies **only to typed flags**; `--body`/`--set` remain pass-through (they are the explicit escape hatch and must never be rewritten). Warning is a structured envelope entry, stable code `legacy_value_coerced`, details naming `field`, `given`, `sent`. Canonical inputs pass unwarned.
3. **No advertised-but-broken surfaces — resolved by removal, not implementation.** `websets imports create --csv/--url` are **removed** in 0.5.0. Rationale: the documented flow is create → PUT to a presigned `uploadUrl`; without a resumable-upload command, a failed PUT strands a created import, and no honest `retryable` value exists for the composite (D7 defines retryable as "safe to retry the exact request"). Instead, `websets imports create` gains a `nextActions` entry carrying the documented second step (exact `curl -X PUT --data-binary @file -H 'Content-Type: text/csv' <uploadUrl>` template) so the two-step flow is discoverable in the envelope itself. A designed one-shot convenience (with resumable upload + pending-record semantics) is deferred to 0.6 and noted in D40.
4. **Docs-only endpoints follow the `/context` precedent exactly**: overlay stores method, path, provenance URL, and request-field metadata only; `body_schema=None`; responses are opaque upstream `data` verified by fixtures + live smoke. `websets exports create <webset-id> --format csv|json` (required, no default — the docs show no default) and `websets exports get <webset-id> <export-id>`. Exports join the parity-test exception list beside `context` (`tests/openapi_parity.rs`). `exports create` → `nextActions` pointing at `exports get`.
5. **Crawl-date fields: document, don't build.** The CLI has no typed crawl-date flags today and the docs audit says not to add deprecated fields for parity. Re-vendoring picks up `deprecated: true` in the spec; generated help/robot-docs surface it. No new warning machinery.
6. **Discoverability beats `--set`, sparingly.** New named flags: `search --output-schema JSON`, `search --system-prompt TEXT`, `agent runs create --system-prompt TEXT`, `contents --highlights [QUERY]`. Everything else stays on the documented escape hatches.

## Verification tiers

1. **Offline request-shape goldens** — every new/changed flag and coercion (dry-run, no network), both search and similar, canonical + legacy + provider cases.
2. **Billing-free credential checks** — capabilities/schema/robot-docs surfaces; doctor.
3. **Authorized live reads** — `search --category publication` (typed path), legacy alias coercion live, `websets get --expand items` against a real webset.
4. **Idempotency-keyed live creates with cleanup, no auto-retry** — `websets exports create --format csv --idempotency-key <k>` on a throwaway webset, poll `exports get`, then delete the webset. Research stub needs no live probe (it never reaches the network).

Coordinator owns tiers 3–4 (the v0.3.0 lesson: offline goldens cannot validate upstream body schemas).
